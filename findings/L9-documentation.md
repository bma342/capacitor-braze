# L9 — Documentation Contract

## Verdict
- 0.1.0 ready: **PASS with cleanup recommended** (no blockers; ~15 minutes of cleanup before 0.1.0 would tighten credibility)
- Braze-senior review: **GAP** (line-number drift across MDCs + a few stale strategic-doc claims would draw red ink from a careful reviewer; nothing structurally wrong)

## Summary
The user-facing docs (README, CHANGELOG, REVIEW_READINESS §6, MDC C10) are honest, current, and accurate against the code. The MDC set's *rules* match what the code does — all eleven contracts are observed in practice. The drift is concentrated in two narrow places: (1) `file:line` references inside MDCs (most lines are off by 50-100 lines because the source files grew since the MDCs were written), and (2) PLAN.md + the plugin's own CLAUDE.md, which still read as pre-scaffold strategic documents with stale SDK pins (34.x / 12.x.x) and an obsolete podspec filename. SDK_SURFACE.md has two specific contradictions in §1 where methods listed as not-shipped on L99 are simultaneously marked **v0.1** (i.e. shipped) in the capability matrix.

## Status-table drift

- **PLAN.md:** Significantly stale. L5 "Status: Planning → scaffold next" is two months behind reality. Week-1/2/3 checkboxes (L293-319) all unchecked despite tasks done. Pins quoted in Week 2 (L305-306) are 34.x / 12.x — wrong. `@bma342/capacitor-braze` package name (L318, L394) is wrong (real is unscoped `capacitor-braze`). Strategic narrative is still useful; the operational status is fiction.
- **REVIEW_READINESS.md:** Section 6 is the canonical "current state" doc and is accurate (post-Phase-S audit). Minor staleness: L412 says 68 tests vs L339's 91 vs README's 92. L7 listed test counts have churned 53 → 68 → 71 → 74 → 92 across recent commits; some refs trail. Section 7 blockers list is accurate (smoke test still ◌, signed commits + npm 2FA still ◌).
- **SDK_SURFACE.md:** The L72 "Currently shipped (as of 0.0.12)" enumeration is accurate (verified via grep against definitions.ts). However the capability matrix at §1 has the bold-vs-not-bold contradiction (F4): rows for `requestPushPermission` / `getBanner` / `isInitialized` / IAM listener / etc. show **v0.1** when the L99 prose says they're not yet shipped. The matrix is the more visible artifact and currently overstates shipping status.

## What's good

- **README** — quick-start API names match `src/definitions.ts` exactly. Disclaimer prominent at top (L9-13) with explicit "NOT made by, affiliated with, endorsed by, or supported by Braze, Inc." Status table is fresh + honest. Internal links all resolve.
- **CHANGELOG** — exemplary. Keep-a-Changelog format, human-readable narrative per entry, every release has rationale + cross-platform implications + breaking-change callouts (e.g. podspec rename at L447). The single most credible artifact in the doc set.
- **REVIEW_READINESS §6** — line-by-line audit of every quality-bar claim with status legend (`✓/○/◌/⚠️`). Honest about gaps (`Layer 4 ◌`, native test harnesses pending). No aspirational pass-marks.
- **C10** — pinned to the actual demo's config. Verified all four requirements (iOS Podfile + Android compileSdkVersion + AGP + Gradle wrapper) match exactly. The only MDC where every claim was verifiable line-for-line.
- **C11** — accurately marked "Not yet implemented." Design doc rather than aspirational claim.
- **SECURITY.md** — has all 15 sections referenced from other docs (verified structurally; deep content out of scope per audit task).
- **CONTRIBUTING.md** — concise, accurate, points to right MDCs.
- **MDC cross-references** — virtually all `[C0X](./C0X-*.md)` links resolve. Most external links to `SECURITY.md §N` / `SDK_SURFACE.md §N` work via auto-generated GitHub anchors.

## What's risky

- **MDC line-number drift** (F7-F12). Eight of eleven MDCs cite stale `file:line` refs that drift by 50-200 lines. A new contributor opening C01 and scrolling to "web.ts:388" lands on whitespace inside `loadSdk`, not `requireInitialized`. Erodes trust in the MDC discipline. Cheap fix: replace numeric refs with symbol refs (`requireInitialized`, `validatePurchase`) which don't drift; or add a CI check that grep-validates all `file:line` MDC refs on every push.
- **C02 iOS worked example is fabricated** (F5). Anyone reviewing the MDC vs the code will conclude the docs lie. The behavior likely produces correct DTOs via BrazeKit's JSON encoder, but the example doesn't describe the implementation. Highest-priority correctness fix in the MDC set.
- **C02 silently absorbs the iOS content-card divergence** (F6). The Swift code admits its serialization "may differ from the Web SDK shape that C02 designates as plugin-canonical." A senior Braze reviewer reading C02 and trusting it would be surprised by the actual wire format. This is the single load-bearing claim of C02 ("Web SDK is canonical, bridges convert") with a known counterexample undocumented in the MDC.
- **SDK_SURFACE matrix overclaims** (F4). The capability matrix is the headline artifact for "what does this plugin do." Marking unshipped methods as **v0.1** misleads at the surface a Braze devrel skim would hit first. The L99 disclaimer is below the fold.
- **PLAN.md frozen at scaffold-stage** (F3). Reading the docs in their nominal order (PLAN → SDK_SURFACE → README → MDCs), the first document a reviewer sees claims the project is unbuilt. Either rewrite the status preamble or add a banner pointing to REVIEW_READINESS §6.
- **plugin CLAUDE.md still has 34.x/12.x.x pins** (F1). Reduces the credibility of the AI-dev-guide doc that contributors use as their reading entry point.
