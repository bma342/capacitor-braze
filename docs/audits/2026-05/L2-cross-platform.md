# L2 — Cross-platform translation (C03)

## Verdict
**GAP** for 0.1.0
**GAP** for senior-dev review

## Summary
The easy stuff is right: 1-indexed month, UTC-pinned DOB, ISO 4217 currency required, gender mapped via per-platform constants, FCM vs APNs token handling, anonymous-user-id sentinel coalescing, BigDecimal.valueOf for Android price precision. Three real cross-platform drifts remain: (1) `BrazeFeatureFlag.properties` and (2) `BrazeContentCard` DTOs diverge between Web (canonical) and native (BrazeKit/Android JSON dumps), with code comments acknowledging the gap; and (3) the documented integer-vs-float distinction in `setCustomUserAttribute` is unfulfillable because JS has only one Number type and native getInt-before-getDouble dispatch erases it.

## What's good
- Currency, price, quantity, month, gender — every "easy" cross-platform translation is correct. BigDecimal.valueOf is the right choice on Android (the C03 worked example matches the implementation exactly).
- UTC pinning for DOB on iOS is the right call and well-commented (ios:316-317).
- Sentinel translation for anonymous-user-id is uniform across all three (`null` on the wire regardless of the SDK's internal representation).
- C03's `registerPushToken` "method legitimately doesn't exist on one platform" pattern is implemented correctly — Web throws with a clear "branch on Capacitor.getPlatform()" message.
- The C03 translation table is a useful artifact that closely matches what the code actually does for ~80% of methods.

## What's risky
- The two DTO shape blockers (FeatureFlag properties, ContentCard type discriminator) ship a contract whose narrowing logic only works on Web. Every iOS or Android consumer who narrows on `type` or unpacks tagged properties hits silent type drift.
- The integer/float JSDoc claim is well-intentioned but the bridge architecture can't deliver it. Better to walk it back than ship a contract that can't be honored.
- C04's "byte-identical error messages" rule is violated for `setDateOfBirth` (and possibly other methods — the audit only spot-checked DOB). Worth a sweep before 0.1.0.
